The AI-generated page

Built with AI

Project 1 asks for a third page generated with AI. This is that page, and rather than hide it behind a generic topic, it documents the thing itself: exactly which generative AI tools touched this site, what they were asked to do, and where the line sits between generated and hand-written.

Disclosure in one paragraph

This page and the initial scaffolding of the whole site were generated with Claude Opus 5 (model id claude-opus-5, 1M-context configuration) running inside Claude Code, Anthropic's command-line coding agent, in September 2026. No other generative AI tool was used. The résumé content, the architectural decisions, and the review of every generated line are mine.

What the AI was asked to do

The work happened as a conversation, not a single prompt. The requests that shaped this site, in order:

  1. Read the Project 1 assignment PDF and the course slides, then list every rubric item and which ones a coding agent could satisfy versus which ones only I could.
  2. Scaffold a personal homepage in vanilla HTML5, CSS3 and ES6 modules — no framework, no build step — using the content of my résumé as the source of truth.
  3. Propose a creative addition that reflects what I actually work on — not a generic widget — then implement it without pulling in a library.
  4. Wire the project to the course ESLint configuration and Prettier, and make the markup pass the W3C validator.
  5. Write a design document covering project description, user personas, user stories and wireframes.

What is generated and what is not

Generated, then reviewed by me

  • The HTML skeleton of all three pages, the stylesheet, and the three ES6 modules in js/.
  • The BM25 retriever in js/retriever.js and its interface — tokeniser, stemmer, ranking and the score breakdown.
  • The force-directed skill graph in js/constellation.js, including the repulsion and spring math and the canvas rendering.
  • This page, end to end.

Mine

  • Every factual claim on the site: roles, dates, publications, metrics. These come from my résumé, not from the model.
  • The decision of what the creative addition should be: a retriever over my own work, because routing and ranking is what I actually do — rather than a decorative animation, or the chess engine I had it build first and then threw away for being impressive but irrelevant.
  • Insisting it be measured against questions I already knew the answers to, before I would believe the ranking.
  • The narrated video, the code review, and the final read-through of every file before submission.

Where the AI was wrong

Worth recording, because it is the part people leave out. Four concrete mistakes caught during review:

  • It invented a Subresource Integrity hash for the Bootstrap stylesheet rather than computing one. A wrong integrity value makes the browser refuse the file silently, so the grid would simply not have loaded. The real hash had to be computed from the actual file.
  • Its first version of the skill graph left one node with no edges, so it floated unconnected in the middle of the canvas.
  • Its first retriever scored cosine similarity over TF-IDF vectors, which over-rewards short documents: asking about “multi-agent orchestration over MCP” returned Pit Wall rather than the AT&T system, purely because Pit Wall’s description is shorter. BM25 normalises by length relative to the corpus average, and fixed it.
  • Even then the query still missed, because my résumé says “orchestrator” while the query says “orchestration”. The stemmer collapsed -ation, -ating and -ated to a shared stem but had no rule for the -ator agent noun, so the two forms never met.

Why disclose this at all

Because the interesting question about a tool like this is not whether it was used, but what you still have to know in order to use it. The model wrote a working BM25 implementation in a few minutes; it also wrote a subresource hash that would have broken the page, and a ranking that was quietly wrong in a way that only surfaced when I tested it against questions I already knew the answer to. Telling those apart is the actual skill, and it is not one you can outsource. The retriever is trustworthy not because a model wrote it, but because it routes 12 of 12 held-out queries correctly and the test file is in the repository.
